# Contributing

1. Create a focused branch and reference the relevant opportunity or control.
2. Use synthetic data only.
3. Update tests and documentation when scoring, prompts, thresholds, or flow behavior changes.
4. Record prompt and scoring formula versions.
5. Require review from both a solution owner and the applicable governance owner for control changes.
6. Never commit tenant exports containing personal connections, credentials, or confidential configuration.

Pull requests should state the business reason, affected users, risk, test evidence, rollback approach, and documentation changes.
